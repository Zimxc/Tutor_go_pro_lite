# TutorWise Lite Pro

Независимая учебная копия TutorWise: репетиторы, подписки, почасовые занятия и домашние задания. Интерфейс украинский, время — `Europe/Kyiv`, цены — UAH. Python 3.12+, Django 5.2 LTS, SQLite, Templates, Forms, ORM, Admin и Pillow.

## Запуск

Папки расположены рядом: `tutor-wise/` — оригинал, `tutor-wise-lite-pro/` — эта версия. Все команды ниже выполняются в `tutor-wise-lite-pro`, рядом с `manage.py`.

```powershell
cd C:\Users\UserPC\Desktop\tutor-wise-lite-pro
py -3.12 -m venv ..\tutor-wise-lite-pro-venv
..\tutor-wise-lite-pro-venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo
python manage.py createsuperuser
python manage.py runserver 127.0.0.1:8002
```

Если активация запрещена PowerShell, используйте `..\tutor-wise-lite-pro-venv\Scripts\python.exe` вместо `python`. На Linux/macOS создайте окружение `python3 -m venv ../tutor-wise-lite-pro-venv` и активируйте `source ../tutor-wise-lite-pro-venv/bin/activate`.

Сайт: http://127.0.0.1:8002/ . Админка: http://127.0.0.1:8002/admin/ . Оригинал может одновременно работать на порту 8000.

В этой локальной копии уже есть независимый снимок исходной SQLite и media. Пользователи и их пароли сохранены, новые действия в Lite не изменяют оригинал. Ключ `.django-secret` создан заново. Имена session/CSRF cookies отдельные, поэтому вход в один проект не вытесняет сессию другого.

Для новой пустой БД `migrate` создаст таблицы, `seed_demo` — предметы. Необязательная команда `seed_demo --with-users` создаёт Анну, Марию, ученика и будущие часы; пароль новых аккаунтов выводится в терминал. Повторный запуск не меняет существующие аккаунты. Уже перенесённые локальные демоаккаунты `anna@tutorgo.example`, `maria@tutorgo.example`, `student@tutorgo.example` используют пароль `TutorGo-Study!2026`. Демопароль не относится к вашим собственным аккаунтам. Пример ссылки Meet не является настоящей созданной видеокомнатой.

## Что сохранено от учебной версии

- Регистрация использует обычный `UserCreationForm.save()`. Создание профиля и транзакция теперь видны непосредственно в `accounts.views.register()`.
- Кабинет показывает ближайший урок, счётчики и ссылки на действия. Вернулось оформление Lite до последнего упрощения.
- У профиля преподавателя две зоны: описание и расписание. Нет отдельного селектора заданий в боковой колонке; задание открывается на странице своего урока.
- В «Мої викладачі» ближайший урок получается понятным запросом в цикле, без специального объекта `Prefetch`.
- `SlotForm.clean_start_time()` напрямую проверяет дату и начало часа. Не создаётся временная модель только ради запуска её `clean()`.
- Публичные страницы наследуют `base.html`, страницы кабинета — `dashboard_base.html` с прежним боковым меню.
- Восстановлены прежние карточки, зелёные акценты, главная с тремя шагами и оформление форм; размеры иконок зафиксированы.

Модели не сокращены искусственно: каждая нужна пользовательскому сценарию. Один небольшой `accounts/decorators.py` оставлен намеренно: `role_required()` проверяет роль, `handle_database_conflicts()` одинаково обрабатывает конфликты SQLite. Без них проверки повторялись бы в каждом View. Слоёв services/selectors/repositories нет.

## Модели: что с чем связано

| Модель | Назначение и связи |
|---|---|
| `User` | Наследует AbstractUser, хранит email, хеш пароля, имя, фамилию и роль student/tutor. Username удалён. UserManager поддерживает create_user/createsuperuser. |
| `StudentProfile` | Один ученик на User через OneToOneField. |
| `TutorProfile` | Один преподаватель на User, фото и описания. |
| `Subject` | Общий каталог с уникальным названием; новые названия добавляет администратор. |
| `TutorSubject` | ForeignKey на преподавателя и предмет плюс цена и 60 минут. Это промежуточная таблица для ManyToManyField. |
| `Subscription` | ForeignKey на ученика и преподавателя плюс дата подписки. |
| `AvailabilitySlot` | Преподаватель и начало конкретного часа. is_listed скрывает удалённый свободный час, сохраняя историю. |
| `Lesson` | Ученик, преподаватель, предмет, слот, статус, цена при записи, ссылка. start_time копируется из слота для ограничения занятости ученика. |
| `Homework` | OneToOneField на Lesson: название, описание, срок. Одно задание на один урок. |

OneToOneField означает «не более одного», ForeignKey — «у одного владельца может быть много записей». Урок ссылается на слот через ForeignKey: отменённые заявки должны оставаться в истории, а тот же будущий час можно забронировать снова.

SQLite обеспечивает уникальный email без учёта регистра, пары преподаватель+предмет и ученик+подписка, преподаватель+час, одно задание на урок, положительные цены и фиксированную длительность. Уроки защищены двумя условными UNIQUE: один активный урок на слот и один активный урок на ученика+час. Активны `pending` и `confirmed`; отменённые/отклонённые записи не занимают время. Преподаватель не пересекает часы, потому что все уроки длятся 60 минут и начинаются ровно в начале часа.

У Lesson цена — снимок значения TutorSubject, поэтому дальнейшее изменение тарифа не меняет историю. `start_time` — такой же серверный снимок начала слота; переноса времени в интерфейсе нет. Межтабличные правила проверяет приложение; произвольная запись через прямой SQL в обход Views не заменяет валидацию.

## Как читать код: от формы к SQLite

Общий путь: **Пользователь → HTML-форма → URL → View → Form → ORM → SQLite → Template/redirect.**

### Регистрация — accounts

`templates/accounts/register.html` отправляет POST в `accounts:register`. View `register()` создаёт `RegistrationForm(request.POST)`. `is_valid()` проверяет email, поля, качество и совпадение паролей. Если есть ошибки, тот же шаблон получает форму с ошибками.

```python
with transaction.atomic():
    user = form.save()
    user.create_profile()
login(request, user)
```

Стандартный UserCreationForm хеширует пароль. `User.create_profile()` создаёт StudentProfile или TutorProfile по роли. Оба сохраняются вместе: ошибка откатывает транзакцию. LoginView и LogoutView используют обычные сессии Django; выход — POST. `AuthenticationMiddleware` устанавливает `request.user`, идентификатор текущего ученика не берётся из браузера. UserManager тоже создаёт профиль в транзакции для программного создания и createsuperuser.

### Подписки — tutors

Кнопка профиля отправляет POST в `tutors:subscription` → `tutors.views.subscription()`. View проверяет роль и выполняет `Subscription.objects.get_or_create(student=request.user.student_profile, tutor=tutor)`. UNIQUE не даёт создать повторную подписку. При отписке удаляется только Subscription, уроки остаются.

`my_tutors()` находит подписанных преподавателей. Для каждой карточки делает простой запрос `tutor.lessons.filter(student=student, status='confirmed', ...).first()`. Только уроки текущего ученика попадают в карточку. Это сознательно простой вариант для небольшого учебного списка.

### Расписание и бронирование — lessons

`SlotForm` проверяет будущее время и ровный час; `schedule()` связывает его с текущим преподавателем. Удалить активный час нельзя; свободный скрывается флагом is_listed.

Форма часа в `templates/tutors/detail.html` отправляет ID слота и предложения в `lessons:book`. В `lessons.views.book()` внутри `transaction.atomic()` создаётся BookingForm, ограниченная выбранным преподавателем и текущим учеником.

```python
offering = form.cleaned_data['offering']
slot = form.cleaned_data['slot']
Lesson.objects.create(
    student=request.user.student_profile,
    tutor=tutor, subject=offering.subject, slot=slot,
    start_time=slot.start_time, price=offering.price,
    status=Lesson.Status.PENDING,
)
```

Цена, ученик и статус задаются сервером. Форма не принимает занятый час, чужое предложение и час другого активного занятия ученика. Последняя защита от одновременных запросов — UNIQUE в SQLite. `IMMEDIATE` начинает транзакцию до чтения, а обработчик IntegrityError/locked/busy после отката показывает ошибку. Сообщение об успехе появляется после успешного выхода из atomic.

`change_status()` сначала находит урок через `participant_lessons(request.user)`. Чужой урок — 404; чужая роль — 403. Преподаватель подтверждает/отклоняет pending, оба участника могут отменить pending/confirmed. Завершить confirmed можно после окончания часа. Изменение статуса не удаляет строку истории.

### Домашнее задание и обычный ModelForm

`homework_edit()` находит собственный подтверждённый/завершённый урок и создаёт `HomeworkForm(..., instance=homework)`. После `is_valid()`:

```python
homework = form.save(commit=False)
homework.lesson = lesson
homework.save()
```

`commit=False` создаёт Python-объект, чтобы добавить урок с сервера до сохранения в БД. В браузере нет поля для подмены владельца. Ученик читает полный текст на защищённой странице урока и в списке собственных заданий. MeetingForm аналогично меняет только ссылку, AccountForm — только имя, фамилию и email. Фото проверяется Pillow, ограничено по размеру и перекодируется в JPEG.

### ORM и шаблоны

`.filter()` строит SQL SELECT, `.create()` — INSERT, `.save()` — INSERT/UPDATE, `.delete()` — DELETE. SQLite хранит результат после завершения транзакции. Миграции создают/меняют таблицы; сам файл БД в Git не входит.

`render(request, 'lessons/detail.html', {'lesson': lesson})` передаёт урок в контекст. В HTML `{{ lesson.subject }}` выводит предмет, `{{ lesson.tutor.user.display_name }}` проходит по связям. `base.html` содержит шапку, сообщения и футер. Публичные страницы переопределяют content; `dashboard_base.html` добавляет меню и dashboard_content для кабинетов. После успешного POST View делает redirect, поэтому обновление страницы не повторяет запись. Пользовательский текст экранируется автоматически.

## Проверки и ручной сценарий

```bash
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py migrate
```

Автоматические тесты, fixtures, pytest и Playwright не добавлены; tests.py пустые. Фактические результаты текущей проверки — в VERIFICATION.md.

1. Откройте оригинал на 8000, Lite на 8002. Проверьте различие названия и независимый вход.
2. В Lite зарегистрируйте преподавателя, добавьте описание, фото, предмет и цену.
3. Добавьте несколько будущих часов. Прошлое время, 10:30 и повторный час должны отклоняться.
4. В другом окне зарегистрируйте ученика, найдите преподавателя по имени/предмету, подпишитесь.
5. Проверьте «Мої викладачі», отправьте заявку на свободный час.
6. Под преподавателем подтвердите её, добавьте реальную ссылку на встречу и задание со сроком.
7. Под учеником откройте ближайший урок, ссылку и домашнее задание. Измените задание преподавателем, затем удалите его.
8. Проверьте отклонение и отмену: будущий час освобождается, история сохраняется.
9. Попробуйте записать другого ученика на занятый слот, а того же ученика — к другому преподавателю на тот же час. Обе операции должны быть отклонены.
10. Чужой ID урока должен дать 404, действие другой роли — 403; без CSRF POST отклоняется.
11. Убедитесь, что изменения Lite не появились в оригинале. Перезапустите Lite: его записи остаются в собственной SQLite.

## Границы версии

Локальное обучение, один часовой пояс и 60 минут на урок. Нет уведомлений, платежей, повторяющегося графика, переноса, API и встроенной видеосвязи. Завершение урока вручную. Список подписок делает дополнительный запрос на карточку; для большого каталога снова понадобилась бы предзагрузка. Старые фотографии после замены не удаляются автоматически. Нужные правила не удалялись ради сокращения числа строк.


## Оформление Pro

Это третья независимая копия, с сохранённым оформлением Lite до последнего визуального упрощения. `tutor-wise` и `tutor-wise-lite` остались без изменений. Код бронирования, модели и защита от пересечений взяты из текущего Lite.

Восстановлены `templates/` и `static/css/site.css` из сохранённой версии: зелёная палитра, прежняя главная, карточки и боковое меню кабинетов. `templates/base.html` — общая шапка, `templates/dashboard_base.html` — оболочка кабинета. CSS находится в одном файле; это прежний визуал, включая его декоративные стили.

У Pro собственные `db.sqlite3`, `media/`, `.django-secret`, cookies `tutorwise_lite_pro_sessionid` / `tutorwise_lite_pro_csrftoken` и переменные `TUTORWISE_LITE_PRO_SECRET_KEY`, `TUTORWISE_LITE_PRO_DEBUG`. База — независимый снимок текущего Lite. Профили и пароли сохранены, но дальнейшие изменения между проектами не синхронизируются.

Для одновременной работы используйте порты 8000 (оригинал), 8001 (Lite), 8002 (Lite Pro). Фактически выполненные проверки этой копии записаны в VERIFICATION.md.
